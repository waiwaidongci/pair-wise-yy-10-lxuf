# zfl-42 批缝补灰与复阴准入台

在原小型漆线雕工坊管理基础上扩展的批缝补灰 + 复阴准入静态应用，直接打开 `index.html` 即可使用（建议用本地静态服务器，例如 `python3 -m http.server`，避免浏览器对本地文件的限制）。

## 文件结构（规则 / 存储 / 页面三个业务文件）

- `js/rules.js` —— **业务规则层**，纯函数，不碰 DOM 与 localStorage：
  批次可用性、初称/称重校验、失重比例、输入指纹、准入判定口径全部在这里。
- `js/storage.js` —— **存储层**，唯一数据入口：localStorage 读写、旧版数据迁移、
  补灰单/柜位/批次的全部变更、判定结果缓存与并发合并、统一履历。
- `js/page.js` —— **页面层**，只渲染和收事件：看板、批次、柜位、履历与所有弹窗操作；
  数据一律经 `QXStore` 变更，判定一律问 `QXRules`。
- `index.html` —— 布局与样式，按顺序加载上述三个文件。

## 业务规则

- 每件作品**同时仅一张未结束补灰单**（补灰中 / 占阴干中）；重复开单沿用首次单据。
- 补灰批次**停用**或**含水率超过 12%** 时不得占阴干位（开单与占位两道都拦，柜位先空先占，重复占位沿用首次结果）。
- 修补后先登记修补人与初称重量；随后由**与修补人不同的人**进行两次称重，
  两次都须距上一节点（初称 / 上一次称重）**满 24 小时**。
- 两段失重比例（克重差 / 上一节点重量）都须落在 **0.200%–0.600%**，且**批缝确认闭合**，
  同时批次仍合格，才**准入金粉**：单据结束、释放柜位、作品进入金粉工序；
  任一不满足即**继续占位**，不释放柜位。
- **胎体或纹样修正**会使准入失效并按新值重算：
  - 已准入的单据作废、作品退回待阴干，需重新开单；
  - 未结束单据清空初称/两次称重/批缝标记，占柜单据继续占位重测。
- **重复或并发**准入请求：判定结果按输入指纹缓存（胎体/纹样、批次状态含水率、初称、两次称重、批缝、占位任一变化即换指纹），并发请求合并为同一个 Promise，沿用首次结果；已准入结论不可变。
- 看板、柜位、履历同源于同一份持久化状态（`qxRepairConsole.v1`），刷新后一致；旧版 `zfl42Works` 数据首次打开时自动迁移。

## 页面操作

- 看板卡片上直接完成：开补灰单（登记修补人/初称）→ 占阴干位 → 两次换人称重 → 批缝闭合 → 准入判定。
- 下方面板：补灰批次维护（停用/含水率）、阴干柜位占用一览、统一操作履历。
- 卡片详情含单据完整时间线；支持缺陷记录、胎体/纹样修正、筛选排序与 JSON 导出。
