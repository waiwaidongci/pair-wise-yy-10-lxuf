# zfl-42 批缝补灰与复阴准入台（小型漆线雕工坊）

独立静态前端应用，直接打开 `index.html` 即可使用（普通 `<script>` 加载，无需构建，
也可通过 `file://` 打开）。在原漆线雕工序看板（贴线中 / 待阴干 / 上金粉 / 待交付）
之上，扩展了批缝补灰、复阴称重与金粉准入闭环。

## 文件分工

| 文件 | 职责 |
| --- | --- |
| `rules.js` | 纯业务规则：批次可用性、失重比例、换人/24 小时间隔、准入判定、判定指纹、并发与重复结果复用。不碰 DOM 与存储。 |
| `storage.js` | 存储层：作品、补灰批次、补灰单、柜位占用的 localStorage 持久化，履历写入（作品 `logs` + 补灰单 `events`），批次规则对账。 |
| `page.js` | 页面层：看板卡片、补灰批次面板、阴干柜位视图、统一履历、作品详情与补灰单台弹窗。所有视图取自同一份快照，写操作后整体刷新。 |
| `index.html` | 结构与样式，仅负责按序引入三个业务文件。 |

## 业务规则

1. **一件作品一张未结束补灰单**：存在开放补灰单时禁止再开；补灰单结束（准入或作废）后才可再开。
2. **批次闸口**：补灰批次停用，或含水率 **> 12%** 时，不得占用阴干柜位；已占用的在批次改坏时
   由对账逻辑清退（操作时拦截 + 每次打开页面刷新时对账，双保险）。
3. **复阴准入**：修补后由**非修补人**称重，两次称重**间隔满 24 小时**；两次失重比例
   （相对前值）均须落在 **0.20%～0.60%**，且**批缝闭合**，才准入金粉。
   任一条件不满足则判定不通过，**继续占用柜位**。
4. **判定结果复用**：胎体、纹样、批次状态/含水率、柜位、称重、批缝等构成判定指纹；
   指纹不变时重复申请直接返回首次结果，并发点击共用同一次判定（in-flight Promise）。
5. **修正作废**：胎体或纹样被修正后，旧准入结果立即失效并按新值重算；若作品已上金粉，
   退回待阴干。批次被停用/含水率调整同样使相关补灰单缓存失效。
6. **准入收口**：判定通过后执行「准入金粉」，补灰单结束、柜位释放、作品进入「上金粉」。

## 视图

- **看板**：四张工序列；卡片内嵌补灰单片段（批次、柜位、两次失重比例、批缝、判定徽标），
  提供「补灰单台 / 准入判定 / 准入金粉」入口。
- **补灰批次面板**：新增批次、调整含水率、启停；违规批次直接标红并提示占柜后果。
- **阴干柜位**：A1–A3、B1–B3 六格，占用作品/批次一目了然，违规占用红格。
- **统一履历**：作品流转与补灰单事件合并时间线；作品详情内也有按时间倒序的合并履历。
- 看板、柜位、履历均从同一存储快照渲染，刷新页面或跨标签页（`storage` 事件）后保持一致。

## 补灰单台操作流

① 选空闲柜位占位（批次不合格时按钮逻辑在存储层拦截）→ ② 登记修补人/初重/完成时间 →
③ 换人、隔 24 小时提交两次称重（区间外可记录但判定不通过）→ ④ 确认批缝闭合 →
⑤ 发起准入判定 → 通过后「准入金粉并释放柜位」。

## 其他

- 数据存于 localStorage（`qfl42Works` / `qxf42Batches` / `qxf42Orders` / `qxf42Version`），
  「恢复演示数据」可一键重置；演示数据含一张已具备准入条件的补灰单与一张被含水率闸口拦截的补灰单。
- 「导出 JSON」导出作品、批次、补灰单、柜位的完整快照。
